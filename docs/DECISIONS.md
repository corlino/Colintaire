# Decisions log

Choices made during implementation that the PRD, Style Guide and TAD §2 do not cover.

| Date | Area | Decision | Why |
|---|---|---|---|
| 2026-11-23 | Vegas payouts in Classic | The engine only tracks `credited`/`everPaid` when the game mode is Vegas. | Keeps Classic state clean; the ledger only reads Vegas games. |
| 2026-11-23 | Session logic placement | New game / restart / reset balance are pure functions in `src/store/session.ts`; the Zustand store (M4) wraps them. | Lets the PRD 6.2 ledger example be unit-tested without React. |
| 2026-11-23 | Tooling versions | TypeScript 6, Vite 8, Vitest 5, Motion 14 (latest stable at project start; TAD lists minimums). | TAD §4: use latest stable. |
| 2026-11-23 | Card corner index | Each corner row shows rank and suit side by side: top row rank-left/suit-right, bottom row suit-left/rank-right, both upright. | Matches the concept screenshot and keeps both rank and suit inside a narrow fanned strip in either orientation (U20). |
| 2026-11-23 | Centre pip | Placeholder faces show one large centre suit symbol. | TAD §12.3; only visible on uncovered cards. Replaceable via the card-face registry. |
| 2026-11-23 | Folded spacing | After folding, leftover column space is shared back to the unfolded face-up strips (up to natural spacing). | Folding saves whole-card steps and otherwise left up to ~50 px unused between rows; the 8 px row gap is still guaranteed. |
| 2026-11-23 | Shell heights | Header 72 px, stats 68 px, 12 px gap above stats, 8 px below; board fills the rest. | Style Guide recommended ranges; one constant set (`src/ui/shellSizes.ts`) shared by UI and layout tests. |
| 2026-11-23 | Peek panel picking | Tapping a face-up card in the peek panel selects it (and the cards above it) and closes the panel; the player then taps a destination. Dragging from inside the panel is not supported. | TAD §9.4 asks for dragging from the panel; tap-to-select covers the same need (moving from the middle of a folded run) with far less input complexity. Revisit if it feels clumsy on device. |
| 2026-11-23 | Selection outline | The picked card gets a 2 px turquoise (accent) outline; the rest of the run lifts without an outline. | Style Guide 6.1 asks for a visible lift or outline; white or grey outlines vanish against white cards and the dark board. Turquoise is the only existing accent. |
| 2026-11-23 | Tap hit-testing | Taps and presses find cards from layout positions, not the DOM. | A card still animating into place can be tapped where it is going; found in manual testing (a double-tap during the 180 ms draw animation missed). |
| 2026-11-23 | Vegas hint | The New Game modal shows one line under the selector when Vegas is chosen: "Costs $52 to deal. Each card on a foundation pays $5." | Makes the virtual buy-in clear before confirming. Easy to remove. |
| 2026-11-23 | Saved timer | The game record stores the timer halted at save time; on launch it resumes from that value. | Time while the app is closed or backgrounded never counts (U11). |
| 2026-11-23 | Restore without deal animation | A restored game appears in place; the deal animation plays only for new deals. A game saved after its win reopens on the win modal. | Reopening the app should look like returning to the game, not a new deal. |
| 2026-11-23 | Partial corruption | Each record (settings, Vegas, game) is validated and discarded on its own. If only the game record is lost, the live Vegas game's buy-in is lost with it (the balance shows the settled amount). | Simplest safe fallback; the case needs storage corruption to happen. |
| 2026-11-23 | Update moment | A waiting service-worker update is applied right after any new deal (New Game confirm or Restart), after saving. | TAD §15.3 names "when a new game is confirmed"; Restart is an equally safe moment. |
| 2026-11-23 | Icon pipeline | `npm run assets` (sharp) builds app icons into `public/icons` from `art/icons/icon-1024.png`, or a placeholder from the card back on #101010. Maskable icon keeps art in the central 60%. | Starts the M6 asset pipeline early because the PWA needs icons now. |
| 2026-11-23 | Art pipeline output | `npm run assets` writes WebP into `public/art/…` and a generated list `src/assets/generated.ts`; the registry overlays it. Cards 300×420, backgrounds 1290×2796 (wide 2560×1440), previews 128×128. Wrong-sized PNGs are cropped to fit with a warning. | Dropping PNGs in `art/` and running one command swaps the art with no code edits; a new folder becomes a new Appearance option automatically (TAD §12.5). |
| 2026-11-23 | Card-face sets | A face set is used only when all 52 files are present. Phase 1 has no face picker, so a supplied set takes effect when its folder is named `classic`. | Partial sets would mix art and placeholder faces mid-game. |
| 2026-11-23 | Keyboard and screen-reader play | Each pile has an invisible focusable button (pointer-events: none). Enter/Space selects the top card, again on the same pile reaches one card further down, Enter on another pile moves, F sends to a foundation, Escape cancels. A polite live region announces draws, moves and refusals. | Not required by the PRD; makes desktop and VoiceOver play possible without touching the touch model. |
| 2026-11-23 | Focus and cursor | Global 2 px white `:focus-visible` outline and pointer cursor on buttons, radios and the stock; controls get a faint hover ring on hover-capable devices. | TAD §13 asks for a visible focus ring on desktop. |
| 2026-11-23 | Screenshot baselines | Playwright keeps baselines of the game, Appearance and New Game screens for iPhone 13 mini only, with time frozen and the version string masked. | One device is enough to catch visual regressions; baselines are per platform. |
| 2026-11-23 | Smaller stats text (owner request) | Stat labels 17 px (was 20); values 20 px, stepping to 17 px at 6 characters and 15 px at 7+ (e.g. −$1040, 1:02:05). Icons 18 px; panel padding 8 px under 400 px wide. | Owner: values such as −$104 were truncated with "…". Overrides the Style Guide 4.2 stat sizes. Checked to fit at iPhone SE width. |
| 2026-11-23 | Preview circles crop, never stretch (owner request) | Theme and card-back previews are drawn at their real proportions (portrait screen, 5:7 card) and centre-cropped to the circle. Generated theme previews use the full background image; the separate preview.webp is dropped. | Owner: the card back was squeezed into a square. |
| 2026-11-23 | CI | GitHub Actions runs check, build and Playwright (Chromium + WebKit) on every push and pull request. Screenshot comparison is skipped on Linux CI because baselines are recorded on macOS. | TAD §15.4. Branch protection on `main` is an owner setting in GitHub. |
| 2026-11-23 | Release tag | Version 1.0.0; the `v1.0.0` git tag is created after the owner's iPhone sign-off (docs/ACCEPTANCE.md). | TAD §17 M7 makes final sign-off owner input. |
| 2026-11-23 | Header logos (owner art) | The crowned-club mark (`art/brand/logo-silver.png`) sits at both ends of the header: logo · short line · SOLITAIRE · short line · logo, 32 px tall (36 px from 400 px wide). Without a logo file the header falls back to full-width lines. `art/brand/logo-dark.png` is kept for light backgrounds but not used yet. | Owner reference screenshot. TAD §12.5 has no brand-mark entry, so `npm run assets` now trims `art/brand/logo-<name>.png` and writes 256 px tall transparent WebP. |
| 2026-11-23 | App icon (owner art) | `art/icons/icon-1024.png` (converted from the supplied WebP) fills the icon edge to edge, including the maskable version, since the artwork already sits inside the central safe zone. Icons are saved without palette reduction so the gradient does not band. | Owner supplied the icon. |
| 2026-11-23 | Rendering performance | The clock lives in the stats panel (re-renders once a second, nothing else does); the board is memoised and passes stable props so unchanged cards skip rendering; the card flip is a CSS keyframe animation (compositor-run, no lasting 3D transform) instead of a Motion rotateY with `perspective` on every card. | Owner noticed uneven animation. Measured at 6× CPU slowdown, iPhone 13 mini viewport: idle script time 138 → 10 ms per 2 s; dropped frames while drawing 15 → 0 and while dragging 2 → 0. |
| 2026-11-23 | Deal animation | The deal flight is a Web Animation (`element.animate`, compositor-run) rather than per-frame JavaScript; cards fly face-down and face-up cards turn over as they land; the new stock is placed instantly; a cold-launch deal waits 0.25 s so it doesn't overlap first paint. Any later move on a card finishes its flight at once. | Owner found the initial deal uneven. Tracing showed startup and React work stalling the JS-driven flight; compositor animations keep running through main-thread work (confirmed in a Chrome trace). |
